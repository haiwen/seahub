# MySQL 到达梦数据同步流程

本文描述 Seahub 从 MySQL 迁移到达梦的推荐全量同步流程。当前主流程使用 `dmpython_import.py` 直接从 MySQL 读取并通过 dmPython 参数绑定写入达梦，不依赖中间 SQL 文件和 `disql`。

## 1. 迁移前准备

1. 确认源 MySQL 的 Seahub 数据库已升级到与目标达梦 DDL 一致的版本。
2. 确认迁移机可同时访问 MySQL、达梦。
3. 安装 Python 依赖并验证：

```bash
python3 -c 'import pymysql, dmPython; print("drivers available")'
```

4. 确认达梦目标库已创建，迁移账号具备建表、插入、清表和查询权限。
5. 为避免命令行历史记录保存密码，建议使用迁移专用账号，并使用环境变量保存连接串：

```bash
export MYSQL_CONNECTION='mysql_user/mysql_password@mysql_host:3306/seahub_db'
export DAMENG_CONNECTION='dm_user/dm_password@dm_host:5236'
```

连接字符串限制：密码不能包含 `/` 或 `@`。如包含这些字符，需要使用迁移专用账号或调整 `dmpython_import.py` 的参数解析逻辑。

## 2. 创建达梦空库结构

1. 在达梦创建目标数据库和迁移用户。
2. 使用 `dameng.sql` 创建 Seahub 数据表和索引：

```bash
/dm8/bin/disql "$DAMENG_CONNECTION" < ./dameng.sql
```

3. 确认 `AVATAR_UPLOADED` 已创建，且 `DATA` 字段为 `CLOB`：

```sql
SELECT "COLUMN_NAME", "DATA_TYPE"
FROM "ALL_TAB_COLUMNS"
WHERE "TABLE_NAME" = 'AVATAR_UPLOADED';
```

4. 如果 `dameng.sql` 含有系统初始化数据，先确认其与源 MySQL 数据不会产生主键或唯一键冲突。全量迁移通常应使用空目标库。

## 3. 迁移前校验

1. 在源 MySQL 统计需要迁移的表行数：

```bash
./count_mysql_tables.sh
```

2. 保存统计结果，用于迁移后核对。
3. 在测试环境先选择至少以下表验证迁移逻辑：

```text
AUTH_USER
AVATAR_AVATAR
AVATAR_UPLOADED
FILETRASH
FILEHISTORY
```

其中 `AVATAR_UPLOADED` 验证 CLOB/Base64 大字段，`FILETRASH` 和 `FILEHISTORY` 验证列映射。

## 4. 源端停写并确保一致性

全量切换前，必须保证迁移期间源数据不再变化。

1. 停止 Seahub 写入请求，或将服务切换为维护模式。
2. 停止后台会写入数据库的任务。
3. 确认 MySQL 当前无持续写入事务。
4. 记录停写时间和源库行数统计结果。

`dmpython_import.py` 会逐表读取 MySQL 数据。若源端持续写入，表之间可能来自不同业务时点，不能保证外键和业务数据一致。

## 5. 执行全量导入

### 5.1 单表试运行

先执行用户表和头像大字段表，验证连接、类型和 CLOB 写入：

```bash
python3 ./dmpython_import.py AUTH_USER \
  --mysql "$MYSQL_CONNECTION" \
  --dameng "$DAMENG_CONNECTION" \
  --batch-size 500

python3 ./dmpython_import.py AVATAR_UPLOADED \
  --mysql "$MYSQL_CONNECTION" \
  --dameng "$DAMENG_CONNECTION" \
  --batch-size 20
```

### 5.2 清空试运行数据

若单表试运行后需要重新开始全库导入，在确认可以丢弃目标数据时，重建目标库或清空已试运行表。单表重跑可以使用：

```bash
python3 ./dmpython_import.py AUTH_USER \
  --mysql "$MYSQL_CONNECTION" \
  --dameng "$DAMENG_CONNECTION" \
  --truncate-target
```

注意：带外键依赖的表不应随意单独 `TRUNCATE`。对完整重跑，优先重新创建空目标库。

### 5.3 按依赖顺序导入所有表

确认试运行通过后，使用 `dm_import_order.txt` 指定的顺序执行：

```bash
./import_dmpython_tables.sh \
  ./dm_import_order.txt \
  python3 \
  "$MYSQL_CONNECTION" \
  "$DAMENG_CONNECTION"
```

说明：

- 脚本按 `dm_import_order.txt` 顺序导入，保证父表先于外键依赖表。
- 每个表内按批次提交。默认批次为 50 条；大 CLOB 表 `AVATAR_UPLOADED` 的默认值可接受，内存紧张时应单独使用单表命令并设置 `--batch-size 10` 至 `20`。
- 任一表导入失败时，批量脚本立即停止。
- 已成功提交的表及批次不会回滚。修复问题后，从失败表继续；若需要重跑失败表，先确认可清空目标表，然后加 `--truncate-target` 重新执行单表导入。

## 6. 导入规则

`dmpython_import.py` 会直接读取 MySQL 源表列并构造参数化 INSERT。所有值通过 dmPython 绑定，不拼接到 SQL 文本中。

名称映射规则已内置：

| 源表/列 | 达梦目标表/列 |
| --- | --- |
| `GROUP` | `Group` |
| `FILETRASH.user` | `USERNAME` |
| `FILETRASH.size` | `FILE_SIZE` |
| `FILEHISTORY.size` | `size` |
| `FILEAUDIT.user` | `user` |
| `FILEUPDATE.user` | `user` |
| `PERMAUDIT.to` | `to` |
| `FILEOPSSTAT.number` | `number` |
| `USERTRAFFIC.user` / `size` | `user` / `size` |
| `SYSTRAFFIC.size` | `size` |
| `MONTHLYUSERTRAFFIC.user` | `user` |

参数绑定会直接传递 TEXT、CLOB、JSON 文本、数值和普通时间值，不需要对 JSON 做 `disql` SQL 字面量转义。

## 7. 迁移后校验

1. 统计达梦目标库行数：

```bash
./count_dm_tables.sh
```

2. 比较 MySQL 与达梦统计结果：

```bash
./compare_table_counts.sh
```

3. 对不一致表逐表排查：
   - 源表是否在迁移时仍有写入。
   - 是否因外键顺序导致导入失败。
   - 是否存在目标表初始化数据。
   - 是否已重复执行部分表。

4. 检查头像 CLOB 数据：

```sql
SELECT "FILENAME", "SIZE", LENGTH("DATA") AS "DATA_LENGTH"
FROM "AVATAR_UPLOADED"
FETCH FIRST 10 ROWS ONLY;
```

5. 验证主要业务数据：
   - 登录用户。
   - 用户头像、群组头像显示。
   - 文件库列表和文件访问。
   - 分享链接、群组、组织和权限。
   - 文件历史、回收站和审计记录。

## 8. 自增列与应用切换

1. 导入会保留 MySQL 原始主键值。
2. 达梦目标表含有 `AUTO_INCREMENT` 时，完成数据导入后需要按达梦版本和运维规范校准自增/序列起始值，使其大于表内当前最大主键。
3. 未完成自增值校准前，不要启动新的 Seahub 写入业务，否则可能产生主键冲突。
4. 更新 Seahub 数据库配置，指向达梦数据库。
5. 启动 Seahub，执行登录、写入文件、创建用户或其他会写数据库的验证操作。
6. 确认写入正常后再正式解除维护模式。

## 9. 失败处理和回滚

1. 切换前始终保留原 MySQL 数据库，且不要删除源库。
2. 数据导入失败时，不将应用切换到达梦；修复后继续导入或重建目标空库重跑。
3. 应用切换后出现严重问题时，将数据库连接配置切回 MySQL 并恢复 Seahub 服务。
4. 未确认达梦数据完整和写入正常前，不应对 MySQL 做清理操作。

## 10. 脚本说明

```text
dmpython_import.py            单表 MySQL 到达梦参数化导入器
import_dmpython_tables.sh     按 dm_import_order.txt 批量导入器
dm_import_order.txt           表导入依赖顺序
dameng.sql                    Seahub 达梦空库 DDL
count_mysql_tables.sh         统计 MySQL 表记录数
count_dm_tables.sh            统计达梦表记录数
compare_table_counts.sh       对比 MySQL 与达梦表记录数
convert_mysql_to_dameng.py    旧的 SQL 文件转换方式；通用 dmPython 流程不需要使用
import_dm_tables.sh           旧的 disql SQL 文件导入方式；通用 dmPython 流程不需要使用
```
